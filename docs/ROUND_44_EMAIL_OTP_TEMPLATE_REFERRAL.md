# Round 44 - Email OTP (cut Prelude cost), branded emails, purchase-gated non-withdrawable referral credit

## Issue 1 - Email OTP instead of paid Prelude SMS

The one-time-code verification now delivers the 6-digit code by EMAIL (Prelude SMS commented out, not
deleted, so it can be re-enabled). Decision: the phone code screen collects an email; the phone stays the
account identity.

- Backend `src/services/otp-service.ts`: `createOtp` routes to the email path whenever an email is present
  (generates the code locally, sends via `EmailService.sendOtp`); the Prelude sms/whatsapp send + the
  `verifyOtp` Prelude `checkVerification` are commented out. If no email is supplied it throws a clear error.
- `src/services/auth-service.ts` `verifyOtp(phone, code, referralCode?, email?)`: a brand-new phone user now
  gets the supplied email on file (if not already taken), enabling email password reset later.
  `src/controllers/AuthController.ts` passes `email` from the request body.
- App (`VeloHUB`): the one-time-code screen `app/(auth)/login.tsx` has an Email field; `use-login-form.ts`
  requests via `channel:'email'` + persists the email (`auth-login` store `signupEmail`);
  `use-otp-verification.ts` passes it to `verifyLoginOtp(phone, code, email)`. Web app
  `velocouriersvc.com/dashboard.html` phone-code option updated the same way (email required + sent).
- Prelude stays wired for non-OTP SMS (`notification-service`, ride shared-contact). Transaction pickup /
  delivery codes are generated by `PickupCodeService` and delivered in-app - fully unaffected.

## Issue 2 - Killer email template + "Velo Courier Services"

`src/services/email-service.ts`: new shared `renderEmail(heading, innerHtml, preheader?)` - responsive,
table-based, app palette (trust-blue `#123C86`, action-orange `#F2761A`, ink `#0D1B2E`), branded header bar,
white card, muted footer; no emoji, no em dashes. `sendOtp` (also used by password reset) now shows the code
in an accent box; `sendOrderConfirmation` / `sendDriverAssigned` / `sendDeliveryComplete` / `sendWelcome`
reuse the wrapper. Brand renamed to **"Velo Courier Services"** in templates + the `fromName` default, and in
`SMTP_FROM_NAME` (`k8s/configmap.yaml` + the CI inline patch in `.github/workflows/docker-publish.yml`).

## Issue 3 - Referral: buy first, credit non-withdrawable

- `src/models/wallet.ts`: new `promoBalance` (decimal, default 0) - the non-withdrawable subset of `balance`
  (auto-migrated, `DB_SYNCHRONIZE=true`). Invariant `promoBalance <= balance`.
- `src/services/wallet-service.ts`: `credit(..., promo?)` adds to `balance` (+ `promoBalance` when promo);
  `getWithdrawableBalance = balance - promoBalance`; `debit(..., allowNegative?, withdrawableOnly?)` -
  payouts (`withdrawableOnly`) reject drawing below promo and never reduce it; other debits keep
  `promoBalance = min(promoBalance, balance)`.
- Payout guards now use the withdrawable figure: `payout-service.instantPayout`, `PayoutController.instant`,
  `wallet-service.requestPayout`, `merchant-service` payout. `WalletController.getWallet` returns
  `promoBalance` + `withdrawableBalance`.
- `src/services/referral-service.ts`: `applyAtSignup` only records the PENDING link (no credit at signup);
  `rewardReferrerOnFirstCompletion` (fires on the referee's first completed ride/order) now credits BOTH the
  referrer and the referee as promo (`credit(..., true)`). Result: no credit until the referee buys
  something, and all referral credit is spendable in-app but never withdrawable. Driver/merchant earnings
  (plain `credit`) remain withdrawable.
